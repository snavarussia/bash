# Bash / Nginx: ежечасный мониторинг журналов

Автоматизированный проект: Vagrant создаёт виртуальную машину Ubuntu 22.04 LTS, устанавливает Nginx и инструменты анализа журналов, а затем настраивает отправку отчёта по SMTP каждый час.

## Письмо содержит:

- Временной диапазон, за который собраны события;
- Топ-10 IP-адресов по количеству запросов;
- Топ-10 URL по количеству запросов;
- Строки ошибок из `error.log`;
- Распределение всех обнаруженных HTTP-кодов по количеству.

Скрипт использует `flock`, поэтому параллельные копии не выполняют сбор данных одновременно. Состояние обновляется только после успешной передачи письма SMTP-клиенту. При неудачной отправке следующий запуск повторит тот же интервал.

## Требования на хосте:

- [VirtualBox](https://www.virtualbox.org/)
- [Vagrant](https://developer.hashicorp.com/vagrant)
- Доступ к интернету для загрузки box и пакетов;
- Почтовый ящик с включённым SMTP-доступом и паролем для внешнего приложения.

## Быстрый запуск:

1. Склонируйте репозиторий и перейдите в каталог проекта;
2. Создайте локальный файл настроек из шаблона:

   ```bash
   cp config/mail.conf.example config/mail.conf
   ```

3. Откройте `config/mail.conf` и укажите свои данные;
4. Запустите виртуальную машину:

   ```bash
   vagrant up
   ```

После завершения provisioning Nginx будет доступен на хосте по адресу <http://localhost:8080>. Cron запускает отчёт в начале каждого часа, на 5-й минуте.

## Настройка SMTP

Измените параметры в `config/mail.conf` согласно документации почтового сервиса.

`SMTP_PASSWORD` - именно пароль для внешнего приложения, а не обычный пароль входа в почту. Убедитесь, что у учётной записи разрешена отправка по SMTP.

## Проверка

Посмотреть состояние виртуальной машины:

```bash
vagrant status
```

Подключиться к ней:

```bash
vagrant ssh
```

Проверить журнал cron и конфигурацию Nginx внутри виртуальной машины:

```bash
sudo systemctl status cron nginx
sudo nginx -t
sudo cat /etc/cron.d/nginx-monitoring
```

Запустить отчёт вручную внутри виртуальной машины:

```bash
sudo /opt/nginx-monitoring/nginx-monitor.sh
```

Проверить последнюю успешную контрольную точку:

```bash
sudo cat /var/lib/nginx-monitoring/last_success_epoch
```

Для тестирования создайте запросы к `http://localhost:8080`, например:

```bash
curl -I http://localhost:8080/
curl -I http://localhost:8080/not-found
```

`error.log` содержит ошибки Nginx. Если приложение пишет ошибки в отдельный журнал, его путь и формат необходимо добавить в скрипт отдельно.

## Временной диапазон и ротация журналов

Время начала берётся из файла `/var/lib/nginx-monitoring/last_success_epoch`. При первом запуске скрипт анализирует последний час. Журналы Nginx ищутся с помощью `find`. Поддерживаются текущие и ротированные файлы, включая `.gz`. Время строк сопоставляется с границами отчёта.

Учитывайте, что при первом запуске отчёт может быть пустым, если за интервал не было запросов или ошибок. Записи, добавленные с задержкой в журнал после завершения интервала, могут не попасть в уже отправленный отчёт.

## Безопасность и эксплуатация:

- Пароль SMTP хранится в `/etc/msmtprc` с правами `0600` внутри виртуальной машины;
- Локальный `config/mail.conf` не должен попадать в GitHub;
- Блокировка `flock` предотвращает параллельную обработку;
- Состояние фиксируется только после успешной отправки письма;
- Чтобы применить изменения Vagrantfile или SMTP-настроек, выполните `vagrant provision`;
- Чтобы удалить виртуальную машину проекта, выполните `vagrant destroy` из каталога проекта. Команда удаляет виртуальную машину и её локальное состояние.
